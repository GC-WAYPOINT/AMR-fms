# 층별 이동 제한과 점유 존

[FMS 안내](../fms_server/README.md) · [승강기](elevators.md) · [개발 구조](architecture.md)

교차로·좁은 통로처럼 충돌 위험이 있는 곳을 점유 존으로 지정해 한 대씩 통과시킨다.
층별 제한은 **한 맵에서 동시에 이동 허가를 보유할 수 있는 로봇 수**다.
맵 하나를 물리 층 하나로 운영한다. 한 층을 여러 맵으로 나눈 경우 그 맵들의 정원을 합산하지 않는다.

## 웹에서 설정

1. 상단에서 현장과 맵을 선택한다.
2. **현장 설정 → 선택 맵 교통 제어**에서 동시 이동 허가 대수를 입력하고 적용한다.
   빈칸은 무제한이다. 기본값도 무제한이다.
3. 실시간 맵에서 방향별 **대기 node와 출구 node를 먼저 목적지로 등록**한다.
4. **＋ → 구역 → 점유 존**을 선택해 사각형을 그리고 **진입 방향 추가**로 대기·출구 쌍을 지정한다.
5. 저장하면 새 맵 버전을 전달한다. 모든 로봇의 맵 동기화·위치 확인 후 작업을 배정한다.

존 위쪽 원형 핸들 또는 **구역 회전(°)** 입력으로 중심 기준 회전이 가능하다.
회전한 실제 경계를 기준으로 겹침·진입 차단·차체 이탈을 판단한다. 대기·출구 node는 함께 회전하지 않는다.

선택한 목적지 좌표를 점유 존의 맵 버전에 **복사**한다. 이후 원래 목적지를 이동·삭제해도
존의 node는 바뀌지 않는다. node를 바꾸려면 점유 존을 다시 편집한다.
존 없이 대수 제한만 사용하거나, 대수 제한 없이 점유 존만 사용할 수도 있다.
구형 클라이언트는 점유 존 맵의 작업 배정이 거절된다. FMS와 C++ 클라이언트를 함께 갱신한다.

## node와 존 배치

- 위험한 교차 공간 전체를 존 안에 넣는다. 서로 비켜갈 수 없는 통로는 통로 전체를 하나의 존으로 잡는다.
- 대기·출구는 맵 안의 FREE 위치에 두고 존과 충분히 떨어뜨린다.
  실행 시 로봇 외접원 반지름 `hypot(width, length)/2 + 0.1 m`의 여유를 검사한다.
- 양방향이면 방향마다 대기·출구 쌍을 만든다. 대기 node가 반대편 로봇의 퇴장 경로를 막지 않도록 대기 공간을 마련한다.
- 한 대기 node에는 한 대만 접근시킨다. 후속 로봇은 출발 위치 또는 이전 허가 지점에서 기다린다.
- 존 내부와 차체 여유 경계에는 작업 시작점·목적지를 둘 수 없다. 장기 주차·충전·작업 지점은 존 밖에 둔다.
- 겹치거나 경계를 공유하는 점유 존은 웹 등록 시 거절한다. 서로 너무 가까워 node의 차체 여유가 부족한 경우에도 경로를 만들 수 없다.
- 승강기 칸·도킹 설비와 직선 진입/후진 구간은 점유 존과 분리한다. 미허가 존을 지나는 직선 동작은 로봇이 오류로 차단한다.

FMS는 grid에서 모든 점유 존을 막은 외부 구간과, 지정한 gate의 존 통과 구간을 연결해 경로를 고른다.
존을 지나지 않는 경로가 더 짧으면 그 경로를 사용한다. 로봇은 각 구간의 허가 조건을 유지하며 실제 A* 경로를 계산한다.

## 이동 허가와 점유 해제

1. 층별 이동 허가를 확보한다. 정원이 차면 오더의 노드를 미허가 상태로 보내 현재 위치에서 대기시킨다.
2. 대기 node를 예약한 뒤 그 node까지 허가한다. 다른 로봇의 현재 위치와 예약된 대기·출구의 차체 여유도 검사한다.
3. 대기 node 도착과 정지를 확인한다. 존이 비어 있고 출구 공간도 비어 있으면 존을 예약하고 출구까지 허가한다.
4. 출구 node 통과와 차체 전체의 존 이탈을 확인하면 점유를 해제한다. 다음 외부 구간이나 다음 존의 대기 node까지 진행한다.
5. 오더 종료 후 로봇의 정지와 IDLE/CHARGING 보고를 확인하면 층별 이동 허가를 반납한다.

허가 가능한 작업은 전송 시각·작업 ID 순서로 검사한다. 대기 node에 아직 도착하지 않은 로봇이
이미 도착한 다른 방향의 진입을 막지는 않는다. 대기·출구 node는 작업 진행률에 포함하지 않는다.

층별 정원은 속도가 아니라 **허가 보유 대수**로 센다. 실행 중 일시정지·존 대기·액션 수행 중에는
허가를 유지한다. 작업 없는 주차·충전 로봇은 제외한다. 제한을 낮춰도 기존 허가를 회수하지 않고 신규 허가부터 막는다.
다층 작업은 승강기를 잡기 전에 도착 층 정원을 예약한다. 자리가 없으면 탑승 전 승강장 위치에서 기다린다.

## 상태와 장애 처리

현장 설정에는 이동 허가·대기 node 예약·존 예약과 대기 이유를 표시한다.
실시간 맵에는 대기·출구와 존 상태를 표시하고, 작업 게시판의 **대기·오류**에도 대기 이유를 표시한다.

| 존 상태 | 의미 |
|---|---|
| 비어 있음 | 확인되지 않은 점유나 예약이 없음 |
| 진입 예약 | 한 로봇에 진입을 허가함 |
| 점유 중 | 예약 로봇의 차체가 존에 걸쳐 있음 |
| 확인 필요 | 미허가 점유, 통신 두절, 위치 확인 상실 또는 등록 로봇의 상태 미수신 |

같은 맵의 다른 로봇 상태가 불명확하면 신규 진입을 보류한다. 사용하지 않는 등록 로봇도 확인 대상이다.
전원을 끈 로봇을 단순히 비어 있다고 판단하지 않는다.

취소·오류·통신 두절은 퇴장 증거가 아니다. **예약에 TTL을 두지 않으며 서버 재시작 후에도 유지**한다.
취소된 로봇이 존 안에 있으면 계속 막는다. 로봇을 안전하게 이동·위치 확인한 뒤 존 밖에서 정지 상태를 보고해야 해제된다.
맵 변경만으로 퇴장했다고 추정하지 않는다. 탑승 전에 취소가 확인된 도착 층 예약은 반납한다.
교통 예약·대기 작업이 있으면 맵 활성화·구역/설비 편집과 해당 로봇의 등록 해제·다른 맵 재배정을 차단한다.
예약이 남은 종료 작업도 삭제할 수 없다.

## 교착·정체 감지

FMS 는 1초마다 **wait-for 그래프**를 만든다: "로봇 A 가 B 가 가진 자원(대기 node·점유 존·층 정원·승강기 임대)을 기다림".

| 구분 | 판정 | 이벤트 |
|---|---|---|
| 교착 | 그래프에 순환이 있다 (DFS) | `traffic.deadlock` (같은 순환은 한 번만) |
| 정체 | 이동 중인데 60초 동안 0.3 m 도 못 감, 또는 통행 대기가 180초 초과 | `traffic.stall` (순환에 든 로봇은 교착으로만 알린다) |

현장 설정의 교통 상태와 `GET .../traffic` 의 `deadlocks`·`stalls` 에 로봇과 자원이 보인다. 알림도 열린다 ([운영 제어](operations.md)).

**자동 해소는 아직 로봇에 허가를 내보내지 않은 예약만 회수한다.** 지금 해당하는 것은 탑승 전 도착 층 예약 하나다 (그 층으로 가는 오더를 아직 보내지 않았다). 순환에 든 것 중 가장 늦게 잡은 것부터 회수하고 `traffic.revoke` 를 남긴다.
대기 node·점유 존 예약은 잡는 즉시 통행 허가(`released`)로 나가므로 **자동으로 풀지 않는다.** 이런 교착은 운영자가 로봇을 옮겨야 풀린다.

## 유휴 로봇 비켜주기

대기 node 주변을 확인할 때 **작업 없이 서 있는 로봇**이 길을 막고 있으면, 그 로봇을 같은 층의 가장 가까운 빈 주차 지점으로 보낸다 (`staging` 시스템 작업, [충전과 대기 위치](charging.md)). 주차 지점이 없으면 아무것도 하지 않는다. 같은 로봇은 60초에 한 번만 시도한다.

## 자동문

문이 있는 통로는 점유 존에 문 신호를 더한 **자동문** 으로 설정한다. 진입점에서 문을 열고 통과 완료점으로 지나간다. [자동문](autodoor.md) 참고.

## 막힌 통로 우회

로봇은 한 노드 구간 안에서만 장애물을 돌아가고, 허가 없는 점유 존(자동문 포함)은 벽으로 본다.
그래서 통로가 장애물로 막히면 문을 지나는 길이 있어도 로봇 혼자서는 그리로 못 간다. FMS 가 장애물을 모아서 경로를 다시 고른다.

**맵 전역 장애물** ([obstacles.py](../fms_server/obstacles.py))

- 로봇이 보고한 `State.detected_obstacles` 중 같은 자리에서 30초(`FMS_OBSTACLE_CONFIRM`) 계속 보인 것만 맵 단위로 등록한다.
  움직이는 장애물과 다른 로봇의 몸체는 올리지 않는다.
- 5분(`FMS_OBSTACLE_TTL`) 유지한다. 다시 보고되면 시간을 새로 센다. 서버를 다시 띄우면 비운다.
- **해제**: 어느 로봇이든 장애물에서 1 m(`FMS_OBSTACLE_VIEW_RANGE`) 안으로 지나가는데 그 자리의 장애물을 보고하지 않으면 바로 지운다.
  FMS 는 로봇의 센서 범위를 모르므로 가장 짧은 값을 기본으로 둔다. 센서 범위가 1 m 보다 짧은 로봇이 있으면 줄인다.
- 조회: `GET .../traffic` 의 `obstacles` (좌표·크기·남은 시간). 이벤트: `obstacle.register`, `obstacle.clear`(`reason`: `not_seen`/`expired`).

**경로 선택에 반영**: 새 작업의 gate 순서를 고를 때 등록된 장애물을 막힌 칸으로 본다.
다른 통로나 자동문으로 갈 수 있으면 그쪽으로 보내고, 피할 길이 없으면 장애물을 무시한 경로를 쓴다 (로봇이 그 앞에서 기다린다).
점유 존이 없는 맵에서는 FMS 가 경로를 고르지 않으므로 적용되지 않는다.

**막힌 작업 재경로** (`tick_reroute`, 1초마다)

다음을 모두 만족하면 FMS 가 오더를 다시 만든다.

1. 작업이 진행 중이고 로봇이 `WAITING` 으로 `FMS_REROUTE_WAIT`(15초) 이상 서 있다.
2. 로봇에 허가된 노드가 남아 있다 (허가가 없어서 서 있는 것이면 대상이 아니다). 실행 중인 액션이 없다.
3. 존 예약을 가지고 있지 않다. 한 작업당 `FMS_REROUTE_MAX`(3)번까지, 판단은 60초에 한 번.
4. **등록 장애물이 이 로봇의 길을 실제로 막고 있다**: 로봇이 지금 `detected_obstacles` 로 보고하는 장애물 중 등록 항목(중심 0.3 m 이내)과 같은 것이 있고, 그 장애물이 로봇 앞 경로 3 m 안에서 차체(외접원 + 0.1 m)에 닿는다. 앞 경로는 로봇이 보고한 `local_path` 와 아직 도달하지 않은 오더 노드 순서 둘 다 본다.
5. 지금 위치에서 남은 명령을 장애물을 반영해 다시 고르면 gate 순서가 현재 오더와 다르다.

4번 때문에 다음 경우에는 재경로하지 않는다: 로봇끼리 막힘(다른 로봇 몸체는 등록하지 않는다), 허가를 받고도 선 로봇(이상 주입 `stop_after_release` 등, 장애물을 보지 않는다), 다른 곳에 있는 장애물이 경로 선택만 바꾸는 경우.

동작: `CANCEL_ORDER` 를 보내고 `traffic.reroute` 이벤트를 남긴다 → 로봇이 멈추고 IDLE 이 되면 같은 작업을
`{job_id}-r{N}` 오더로 다시 보낸다. 끝낸 명령은 빼고 남은 명령만 넣으며 (`Job.resume_from`) 진행률은 이어진다.
자동문을 지나는 길이면 진입·통과 노드 쌍이 들어가 문이 열린 뒤 통과한다. 취소가 30초 안에 확인되지 않으면 `traffic.reroute_abort` 로 원래 오더를 유지한다.
다층 작업은 대상이 아니다.

## 경로 교차 예고 (실험)

같은 맵의 두 로봇이 보고한 남은 경로(`State.local_path`)가 5초 안에 차체 반경 합 안으로 가까워지면 `traffic.conflict` 이벤트를 남긴다. 점유 존 밖의 마주침을 미리 알기 위한 것이다.

- 기본은 알리기만 한다.
- 맵 옵션 `conflict_pause` 를 켜면(현장 설정 체크박스, `PUT .../traffic {"conflict_pause": true}`) 우선순위가 낮은 쪽(같으면 나중에 배정된 쪽)을 `PAUSE` 로 세우고, 3초 동안 다시 잡히지 않으면 `RESUME` 한다. 그사이 운영자·현장 정지가 건 일시정지는 풀지 않는다.
- 로봇끼리는 서로를 감지하지 못한다. 이 기능은 경로 예측에 기대므로 충돌 방지 수단이 아니다. 위험 공간은 점유 존으로 막는다.

## 일방통행·감속 구역

- **일방통행 통로**: 구역 종류에서 고른다. 진입 방향(gate)이 하나뿐인 점유 존으로 저장한다. 대기 node 에서 출구 node 방향으로만, 한 대씩 지나간다. 같은 방향으로 여러 대가 잇달아 들어가는 것(정원 > 1)은 차체 간격 검증이 필요해 지원하지 않는다.
- **감속 구역** (`type=slow`, `speed_limit` m/s): 구역 안에서 로봇이 그 속도 이하로 달린다. 주행을 막지 않고 굽지도 않는다. 로봇이 번들의 `annotations.json` 에서 읽어 스스로 제한한다 (AMR-simulator 로봇 클라이언트). 지원하지 않는 구형 클라이언트는 무시한다.

## API와 저장

기존 맵 구역 API에 `type=occupancy`, `gates=[{gate_id, wait:{x,y,theta}, exit:{x,y,theta}}]`를 추가했다.
선택 필드 `rotation`은 중심 기준 회전 각도(도)이며 기본값은 0이다. `x/y`는 회전 전 좌상단 좌표다.
점유 존은 `annotations.json`과 맵 버전 해시에 포함하고 정적 PNG에는 굽지 않는다.

| API | 용도 |
|---|---|
| `GET /api/v1/sites/{site}/maps/{map}/traffic` | 정원, 예약, 존 상태, 대기 작업 조회 |
| `PUT /api/v1/sites/{site}/maps/{map}/traffic` | `{"max_moving_robots": 2}` 설정. `null`은 무제한. `{"conflict_pause": true}` 만 보내면 정원은 그대로 둔다 |

`FMS_DATA_ROOT/traffic.json`에 정원과 예약을 원자적으로 저장한다. 작업 파일의 `traffic`에는
삽입 노드·원래 명령 대응·존 통과 순서를 저장한다. 단일 FMS 프로세스에서 코디네이터 락을 공유한다.

로봇의 점유 존 지원 여부는 Factsheet(`fms/v1/{id}/factsheet`)의 `traffic_control`, 보고하지 않는 클라이언트는 `State.traffic_control` 로 판정한다. `OrderNode.allowed_zone_ids`는 해당 노드로 가는
구간에서 허가한 존 목록이다. 목록에 없는 존은 재탐색·동적 장애물 회피에서도 막는다.
점유 존 맵에서는 정적 맵만 보는 PSO 다듬기를 사용하지 않는다.

존 밖의 로봇 간 교차·마주침·충돌 회피는 제공하지 않는다 (경로 교차 예고는 알림일 뿐이다). 발행된 허가가 얽힌 교착은 자동으로 풀지 않는다.
각 로봇의 물리 월드는 서로 독립적이므로 위험 공간은 빠짐없이 존에 포함해야 한다.

검증 명령은 **리포 루트**에서 실행한다. 물리 시험은 자체 브로커 18851과 임시 데이터만 사용한다.
