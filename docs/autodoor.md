# 자동문

[FMS 안내](../fms_server/README.md) · [교통 제어](traffic.md) · [승강기](elevators.md) · [개발 구조](architecture.md)

자동문은 [점유 존](traffic.md)에 문 제어기 신호를 더한 구역이다. 문 구역을 지나는 경로를 만들면
진입점에서 문 열림을 신호하고, 열린 것을 확인한 뒤에야 한 대씩 통과시킨다.

## 웹에서 설정

1. 문이 있는 맵에서 **＋ → 구역 → 자동문 (진입점 2개)** 을 고르고 문 구역을 사각형으로 그린다.
   통과 방향이 짧은 변이 되도록 문 두께에 맞춰 얇게 그린다.
2. 진입점 **A·B** 는 구역 양쪽 0.8 m 지점에 기본으로 놓인다. 좌표를 고치면 그 값을 쓴다. 두 점은 존 밖의 FREE 위치여야 한다.
3. **문 ID** 는 문 제어기 토픽 id 다. 비우면 구역 ID 를 쓴다. 현장 사이에서도 겹치면 안 된다 (겹치면 422).
4. 저장하면 새 맵 버전을 로봇에 전달한다. 편집 제약(진행 작업·이동 중 로봇이 있으면 409)은 점유 존과 같다.

## 동작

A 쪽에서 들어오면 A 가 **진입점**, B 가 **통과 완료점** 이고, B 쪽에서 들어오면 반대다.

1. 작업을 보낼 때 경로가 문 구역을 지나면 `진입점 → 통과 완료점` 노드 쌍을 오더에 삽입한다 (점유 존과 같은 방식).
   존을 지나지 않는 경로가 더 짧으면 우회한다.
2. 로봇이 진입점에 서서 정지하고 존·출구 공간이 비면 FMS 가 문에 `OPEN` 을 보낸다 (열림 유지).
   문이 열린 것을 `state` 로 확인해야 존을 예약하고 통과 완료점까지 허가한다. 그동안 대기 이유는 `자동문 열림 대기` 다.
3. 통과 완료점을 지나고 차체가 존을 벗어난 것을 새 State 로 확인하면 `RELEASE` 를 보내 문을 닫게 한다.
4. 로봇은 통과 완료점을 거쳐 원래 다음 목적지로 간다. 삽입한 노드는 작업 진행률에 포함하지 않는다.

문 상태를 모르거나(수신 없음·5초 이상 지연) 장애(`mode != NORMAL`)면 열린 것으로 보지 않고 계속 기다린다.
통과 중 취소·장애는 교통 예약과 같이 퇴장 증거가 있을 때만 푼다. 존 예약 전(진입점 대기 중)에 작업이 끝나면 문 붙잡음만 놓는다.

로봇(C++)은 자동문을 모른다. 맵에는 `type=occupancy` 점유 존으로 들어가므로 클라이언트 변경이 필요 없다.
`annotations.json` 의 zone 에는 `door: {door_id, node_a, node_b}` 가 더 들어 있고, `gates` 는 여기서 파생한다.

## 문 제어기 계약

원본은 [common/door_proto.py](../common/door_proto.py)다.

| 토픽 | 방향 | 내용 |
|---|---|---|
| `door/v1/{door_id}/cmd` | FMS → 제어기 | `{cmd_id, type: OPEN\|RELEASE}` (QoS 1) |
| `door/v1/{door_id}/state` | 제어기 → FMS | `{door_id, timestamp, door: CLOSED\|OPENING\|OPEN\|CLOSING, held, mode?, fault?}` (retain) |

`OPEN` 은 "열고 `RELEASE` 까지 유지" 이며 멱등이어야 한다. FMS 는 문이 열리기 전까지 2초마다 다시 보낸다.

## 시뮬레이터

FMS 는 기본으로 `fms_server/door_sim.py` 의 가상 자동문을 띄운다 (`FMS_DOOR_SIM=0` 으로 끈다).
처음 `OPEN` 을 받은 문 id 로 문을 만들고, 열림 1초 → 유지 → `RELEASE` 후 닫힘 1초 동작을 한다 (최대 60초 열림).
실제 제어기를 붙일 때는 내장을 끈다 (같은 토픽에 state 를 두 군데서 내면 안 된다).

## API와 저장

`POST/PUT /api/v1/sites/{site}/maps/{map}/zones` 에 `type=autodoor` 를 추가했다.
선택 필드 `door_id`(기본 zone_id), `door_nodes`(`[{x,y},{x,y}]` = A·B, 기본은 구역 양쪽 0.8 m).
조회하면 `type=occupancy` 에 `door` 가 붙어 나온다. 교통 조회(`GET .../traffic`)의 `zones[].door` 에 문 상태가 있다.
이벤트: `door.open`(문이 열려 진입 허가), `door.fault`(제어기 장애 전환).

## 제약

- 문 구역은 직사각형이고 다른 점유 존과 겹칠 수 없다. 문마다 진입점은 양쪽 하나씩이다.
- 문 제어기 장애 시 자동 우회·재시도는 없다. 열릴 때까지 진입점에서 기다린다 (정체 감지가 알린다).
- 문 구역에는 작업 시작점·목적지를 둘 수 없다 (점유 존 규칙).
